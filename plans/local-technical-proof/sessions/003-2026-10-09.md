## Work Completed

- **P3.1 Snapshot cache:** Added complete schema/digest/reference/capability/floor validation, duplicate and immutable-version protection, atomic swaps, one-second authenticated TLS polling, conditional 304 heartbeats and post-swap acknowledgements. Failed receipts retry on later polls; failed candidates retain the last good generation and contact time. Cold/stale readiness and known-identity revocation lag are explicit.
- **P3.2 Runtime:** Added authenticated batch evaluation, bounded admission before body reading, strict content limits, policy-free client configuration, service-only diagnostics/schema/audit and memory-only turn contexts. Inputs pin policy, binding and configuration; outputs consume the same identity/correlation-scoped context once. Blocks, output completion and expiry release contexts.
- **P3.3 Detector:** Added the versioned local ASCII email/international-phone adapter with maximal-token validation, exact code-point spans and independent segments. Tests cover format boundaries, Unicode surroundings, invalid longer tokens and supported minimum/maximum lengths. Legacy detector support remains separate from proof capabilities.
- **P3.4 Execution:** Added a bounded pool of four persistent isolated subprocesses and 32 queue slots by default, a shared monotonic deadline, 400 ms evaluator cutoff, 100 ms audit reserve, process kill/reap/replacement and clean shutdown. A timed-out request does not wait for cleanup; its admission remains held until both response work and worker cleanup finish.
- **P3.5 Decisions:** Added batch aggregation, normal action ceilings, validated union-of-span redaction, explicit operational failure actions and monotonic audit-failure escalation. The shared redaction helper now merges overlaps/touching spans instead of leaking an overlapping suffix. Invalid findings cannot enter decision/audit metadata.
- **P3.6 Audit:** Added a separate schema-version-1 SQLite audit store, one serialized runtime writer, bounded lock time, restricted files, closed metadata projections, optional authorized retention, scoped keyset reads and transactional, idempotent connector-event ingestion. Conflicting replay IDs and client content/foreign identities reject.
- **P3.7 Federation:** Added verified-TLS management audit/schema forwarding, tenant-scoped delegation, administrator-only content reads with management audit, stable merged pagination and explicit unavailable-source results. Management closes its synchronous audit connections after each query to permit clean runtime shutdown.
- **P3.8 Evidence:** Added and passed fixed runtime inventories, real installed HTTPS management/runtime processes, a delayed HTTPS mock turn, process/queue/storage faults, restart/privacy/retention checks and corrupt-snapshot rejection over TLS. The pinning assertion explicitly requires the newer generation to apply while model inference is still in flight.

## Decisions Made

- Continue in the assigned persistent worktree and branch. The user authorized completion of Phase 3 and a commit; source contracts remained read-only.
- Keep one fixed evaluator module in supervised worker subprocesses. Only validated content/check projections and fixed proof fault selectors cross that boundary; no credentials, caller code or arbitrary import paths are sent.
- Preserve the 500 ms stage budget and 100 ms scheduling tolerance. Queue wait, evaluation and SQLite busy time share that budget. Explicit fault fixtures lower only their recorded cache age, context TTL or worker/queue capacity.
- Validate every complete snapshot before swapping, including already known immutable policy versions. Output contexts retain old objects across updates and rollback. Unknown credentials always reject, including during stale-cache operation.
- Keep retention cases in separate per-test stores. Default queries omit content; raw traffic and secrets are excluded from exported evidence. Connector event durability/replay at the gateway remains Phase 4.
- The live overlay excludes proof fault endpoints. Test-only endpoints require a distinct generated harness credential and accept only fixed fault values.
